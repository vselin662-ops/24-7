# ТЕХНИЧЕСКИЙ ОТЧЕТ: ТЕКУЩЕЕ СОСТОЯНИЕ ПРОЕКТА "АВТОНОМНЫЙ ЦИФРОВОЙ СОТРУДНИК"

## 1. ЧТО УЖЕ СОБРАНО (ФАЙЛЫ, МОДУЛИ И КОМПОНЕНТЫ)

Проект полностью структурирован и содержит следующие основные файлы и модули:

### Серверная часть (Backend)
*   `server.ts` — Основной веб-сервер на Express.js.
    *   **Назначение:** Обеспечивает работу API-интерфейсов, проксирует запросы к ИИ-модели Gemini (для защиты API-ключей), обрабатывает логику онбординг-интервью и симулирует ответы от различных специализированных агентов. Интегрирует Vite-middleware в режиме разработки для бесшовного рендеринга фронтенда.

### Клиентская часть (Frontend / React)
*   `src/main.tsx` — Точка входа клиентского приложения React.
*   `src/App.tsx` — Главный контейнер приложения.
    *   **Назначение:** Управляет глобальным состоянием (конфигурация компании, список активных агентов, выбранная вкладка), координирует переходы между экраном онбординга и рабочей панелью (Dashboard).
*   `src/types.ts` — Общесистемные TypeScript-интерфейсы.
    *   **Назначение:** Описывает структуры данных для конфигурации (`AppConfig`), агентов (`Agent`), SMART-целей (`SmartGoal`), сообщений (`Message`) и симулируемых каналов.

### Интерактивные компоненты UI (папка `src/components/`)
1.  `OnboardingFlow.tsx` — Модуль интерактивного AI-интервью.
    *   **Назначение:** Реализует пошаговое или ИИ-управляемое анкетирование пользователя, сбор требований к бизнесу, автоматическое распознавание нужных настроек через Gemini и инициализацию штаба из 5 агентов.
2.  `SMARTPlanner.tsx` — SMART-планировщик задач.
    *   **Назначение:** Генерирует SMART-цели, декомпозирует их на тактические шаги для каждого из 5 агентов штаба с помощью Gemini API.
3.  `ChannelSimulator.tsx` — Симулятор каналов связи.
    *   **Назначение:** Полноценный чат-интерфейс для симуляции переписки клиентов с агентами в Telegram, WhatsApp, VK и Email. Показывает, как именно боты будут общаться с реальными людьми.
4.  `AnalyticsPanel.tsx` — Аналитическая панель штаба.
    *   **Назначение:** Визуализирует метрики эффективности (конверсии, скорость ответов, сэкономленное время, загрузка каналов) с помощью интерактивных графиков на базе Recharts.
5.  `BillingPanel.tsx` — Тарифы и биллинг.
    *   **Назначение:** Позволяет выбрать тарифные планы, рассчитать стоимость инфраструктуры (OpenVoice v2 + Gemini 3.5 + хостинг) и демонстрирует систему биллинга.
6.  `FAQPanel.tsx` — Академия, промты и соответствие 152-ФЗ.
    *   **Назначение:** Содержит часто задаваемые вопросы, позволяет «заглянуть под капот» и просмотреть/скопировать системные промты ИИ-агентов, а также предоставляет функцию мгновенного и безвозвратного удаления данных (отзыв согласия по 152-ФЗ).
7.  `VoiceRecorder.tsx` — Модуль записи голосового клона.
    *   **Назначение:** Записывает эталонный аудиофрагмент речи владельца через микрофон браузера, вычисляет длительность и симулирует создание безопасного голосового вектора для OpenVoice v2.
8.  `GlassPanel.tsx` & `NeonButton.tsx` — Базовые UI-компоненты.
    *   **Назначение:** Задают единый визуальный футуристический неоновый стиль (Cyberpunk / Glassmorphism) со скруглениями, размытиями заднего плана и неоновым свечением.

## 2. РАБОЧИЕ ФУНКЦИИ (ЧТО МОЖНО ЗАПУСТИТЬ ПРЯМО СЕЙЧАС)

*   **Интерактивный онбординг (AI-интервью):** Реальный диалог с Gemini-интервьюером, который задает вопросы о бизнесе. Реализована кнопка **"Собрать штаб 🚀"** для принудительного завершения интервью — в этом случае ИИ автоматически анализирует контекст беседы, вытаскивает название компании, имя владельца, сферу и генерирует оптимальный JSON-конфиг.
*   **Редактирование параметров компании и ИИ-агентов:** Возможность тонко настроить название бизнеса, сферу деятельности, имя владельца, тон общения, каналы связи, а также вручную отредактировать системный промт (инструкцию) любого из 5 ИИ-агентов.
*   **Генерация SMART-целей и планов:** На вкладке «SMART-планировщик» вы можете ввести глобальную цель бизнеса (например: *"Увеличить продажи на 30%"*), и Gemini сгенерирует детализированный план, расписав конкретные KPI и задачи для каждого агента (приемщика, продажника, контентщика, операциониста, аналитика).
*   **Мультиагентный симулятор каналов связи:** Вы можете выбрать мессенджер (Telegram, WhatsApp, VK, Email), тип клиента (холодный, горячий, конфликтный) и начать чат. Отвечать вам будет именно тот агент вашего штаба, роль которого соответствует выбранной задаче, общаясь строго по инструкции и в рамках специфики вашего бизнеса.
*   **Локальное сохранение состояния:** Все данные штаба, настройки, сгенерированные цели и кастомные промты сохраняются в `localStorage` браузера и не пропадают при перезагрузке страницы.
*   **Удаление данных в соответствии с 152-ФЗ:** Работающая кнопка полного отзыва согласия и очистки всех данных.

## 3. НЕЗАВЕРШЕННОЕ И ПЛАНОВОЕ

### Начато, но работает в режиме симуляции (Mock)
*   **Клонирование голоса (OpenVoice v2):** Компонент записи голоса полностью функционирует (запись звука через `MediaRecorder API` работает), но отправка аудиофайла на генерацию слепка имитируется, так как в песочнице нет развернутой тяжелой GPU-модели OpenVoice.
*   **Реальные интеграции с Telegram/WhatsApp API:** Чат-симулятор имитирует переписку в браузере. Подключение настоящих вебхуков к мессенджерам спроектировано, но требует внешнего публичного сервера и токенов от провайдеров.
*   **Реальная БД (PostgreSQL) и векторная БД (ChromaDB):** Спроектированы в коде, но в текущем контейнере песочницы данные сохраняются локально (`localStorage`), так как внешние базы данных не привязаны.

### Только запланировано (не начато)
*   **Панель ручной модерации сообщений:** Интерфейс, где владелец в режиме реального времени видит сообщения клиентов и одобряет/корректирует ответы агента перед отправкой в мессенджер (для режима `human-supervised`).
*   **Загрузка файлов (базы знаний):** Интерфейс для загрузки PDF, DOCX и прайс-листов, чтобы ИИ-приемщик брал информацию об ассортименте из реальных файлов.

## 4. МОИ ВОЗМОЖНОСТИ В СРЕДЕ AI STUDIO

### Что я могу сделать прямо здесь (внутри песочницы Cloud Run)
*   **Создавать и модифицировать любой Frontend/Backend код** на TypeScript, React, Tailwind CSS и Express.
*   **Делать полноценные серверные запросы к Gemini API** (через официальный SDK `@google/genai`) благодаря бесшовной интеграции ключа `process.env.GEMINI_API_KEY`.
*   **Использовать любые npm-библиотеки** для визуализации данных (Recharts, D3), анимации (motion/react) и иконок (lucide-react).
*   **Управлять локальным хранением данных** в контейнере или браузере (`localStorage`).

### Что требует внешней инфраструктуры (за рамками песочницы)
*   **Тяжелые нейросети для аудио/видео:** Клонирование голоса OpenVoice v2 требует выделенного сервера с GPU (например, Nvidia T4/A100) из-за высоких требований к видеопамяти.
*   **Публичные вебхуки для Telegram/WhatsApp:** Чтобы боты реагировали на сообщения из реальных телефонов, веб-сервер должен иметь постоянный домен, SSL-сертификат и быть доступен извне 24/7.
*   **Постоянная реляционная СУБД:** Хранение истории миллионов переписок требует внешней СУБД (например, Google Cloud SQL / Yandex Managed PostgreSQL).

## 5. АРХИТЕКТУРА И СТЕК ТЕХНОЛОГИЙ

### Стек технологий:
*   **Frontend:** React 18, Vite (сборщик), Tailwind CSS (стилизация), `lucide-react` (иконки), `motion/react` (анимации), `recharts` (аналитические графики).
*   **Backend:** Node.js (v20+), Express.js (веб-сервер), `@google/genai` (официальный SDK для работы с ИИ-моделью `gemini-3.5-flash`).
*   **Хранение данных:** Временное — `localStorage` клиента; Спроектированное в архитектуре — PostgreSQL (структурированные логи и настройки) + ChromaDB (векторное хранилище знаний для RAG).

### Схема взаимодействия:
```
[ Браузер Пользователя (React UI) ]
         │  ▲
         │  │ 1. Пользователь делает запрос (вводит SMART-цель или отправляет сообщение в чат)
         ▼  │
[ Сервер Express.js (Node.js) ]
         │  ▲
         │  │ 2. Проксирование запроса, обогащение системными промтами и контекстом бизнеса
         ▼  │
[ Google Gemini API (модель 3.5-flash) ]
```

## 7. ТЕХНИЧЕСКИЕ ОГРАНИЧЕНИЯ ПЕСОЧНИЦЫ

*   **Отсутствие GPU:** В контейнере песочницы нет графических процессоров. Любые задачи, связанные с локальным запуском OpenVoice v2 или Whisper, невозможны. Мы обязаны использовать сторонние облачные API для аудио-задач.
*   **Временный характер контейнера:** Контейнеры Cloud Run в режиме разработки могут перезапускаться. Файлы, записанные на диск сервера, сотрутся при перезапуске. Именно поэтому локальная база данных SQLite не используется, а приоритет отдан клиентскому `localStorage` или внешним облачным СУБД.
*   **Ограничения фрейма (Iframe Constraints):** Приложение внутри превью AI Studio работает в изолированном фрейме. Некоторые функции браузера (например, прямой доступ к камере/микрофону в некоторых политиках безопасности или всплывающие окна OAuth) могут требовать открытия приложения в новой вкладке.

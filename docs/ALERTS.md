# Документация по оповещениям и мониторингу SELIN Server

Данный документ описывает правила мониторинга, критерии алертов и регламенты реагирования для сервера SELIN в Google Cloud Run.

---

## Таблица правил и порогов алертов

| Название алерта | Условие срабатывания | Серьёзность | Инструкция / Действие |
| :--- | :--- | :--- | :--- |
| **High Error Rate** | >5% ответов 5xx за 5 минут | **Critical** | Проверить логи системы (`level: error`), зафиксировать сбои внешних API (Gemini Outage). |
| **Circuit Breaker Open** | `circuit_breaker_state == 1` (OPEN) > 1 минуты | **Warning** | Основной провайдер Gemini недоступен, автоматически активирован Failover. Проверить квоты API. |
| **Rate Limit Spike** | `rate_limit_hits_total` > 50 запросов в минуту | **Warning** | Возможна DDoS-атака или аномальная активность клиента. Проверить IP в логах. |
| **SQLite Latency High** | Latency p99 > 500ms | **Warning** | Высокая задержка базы данных. Выполнить WAL checkpoint или оптимизацию индексов. |
| **TTS Failure Rate** | >20% ошибок синтеза речи за 10 минут | **Warning** | Проверить лимиты сервиса TTS / Gemini Voice, сократить длительность сообщений. |
| **Tenant Data Leak Attempt** | Зафиксирован несанкционированный запрос к чужому `tenant_id` | **Critical** | Немедленно блокировать подозрительный IP, отозвать JWT-токен пользователя, провести аудит auth. |
| **Disk Usage High** | Размер файла `selin_data.db` > 1 GB | **Warning** | Выполнить очистку или архив устаревших логов и диалогов. |
| **Memory Usage High** | Использование RAM > 400 MB из 512 MB (80%) | **Warning** | Проверить утечки памяти, при необходимости увеличить выделяемые ресурсы Cloud Run. |

---

## Порядок действий дежурного инженера

1. **При получении алерта Critical (High Error Rate, Tenant Data Leak Attempt):**
   - Открыть панели Cloud Logging / Grafana по `X-Request-Id` или `tenantId`.
   - Если зафиксирована попытка несанкционированного доступа к чужим данным (`tenant_id`), отозвать JWT токен и заблокировать IP.
   - При отказе базовых моделей убедиться, что Failover переключил трафик на резервные узлы.

2. **При получении алерта Warning (Circuit Breaker, Rate Limit, Latency):**
   - Оценить масштаб проблемы по метрикам `/metrics`.
   - Проверить наличие блокировок по Rate Limiter.
   - Проверить статус внешних провайдеров (Google Cloud Health Status).

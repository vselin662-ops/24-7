# Инструкции по устранению сбоев (Runbook)

Этот документ содержит простые пошаговые чек-листы для владельца проекта и администраторов на случай возникновения экстренных ситуаций в работе **Selin AI 2.0**.

---

## ЧЕК-ЛИСТ 1: Пропал голос (Бот отвечает текстом, но нет аудио)

Если бот присылает текстовые ответы, но голосовые сообщения отсутствуют или выдают ошибку воспроизведения:

*   [ ] **Шаг 1. Проверить свободное место на диске сервера.**
    *   *Зачем:* Сгенерированные аудиофайлы временно сохраняются на диск перед отправкой. Если диск заполнен на 100%, файлы не запишутся.
    *   *Действие:* Очистить кэш или увеличить диск в панели хостинга (например, Railway).
*   [ ] **Шаг 2. Проверить переменную `APP_URL` в настройках окружения.**
    *   *Зачем:* Мессенджер MAX скачивает аудиофайл по прямой ссылке, генерируемой сервером. Если `APP_URL` указан неверно (например, остался `http://localhost`), MAX не сможет получить файл.
    *   *Действие:* Убедиться, что `APP_URL` совпадает с вашим текущим доменом и начинается с `https://`.
*   [ ] **Шаг 3. Проверить доступность интернета на сервере.**
    *   *Зачем:* Синтез голоса Microsoft Edge TTS работает через облачные серверы Microsoft. Если у бэкенда пропал внешний интернет, синтез упадет с ошибкой соединения.
*   [ ] **Шаг 4. Проверить правильность названия голоса в настройках.**
    *   *Зачем:* Переменная `EDGE_TTS_VOICE` должна указывать на существующий голос Microsoft (например, `ru-RU-DmitryNeural` или `ru-RU-SvetlanaNeural`).
    *   *Действие:* Исправить опечатки в названии голоса в `.env`.

## ЧЕК-ЛИСТ 2: Не ходит рассылка (Например, утренние чтения Библии)

Если подписанные пользователи перестали получать автоматические ежедневные сообщения:

*   [ ] **Шаг 1. Проверить активность подписки в базе данных.**
    *   *Действие:* Сделать запрос к базе данных SQLite: `SELECT * FROM bible_subs;`. Убедиться, что у пользователя стоит статус `active = 1`.
*   [ ] **Шаг 2. Перезапустить сервер приложений.**
    *   *Зачем:* Таймеры и расписания рассылок инициализируются в памяти в момент старта сервера. При случайной перезагрузке контейнера или сбое процесса таймер мог не перезапуститься.
    *   *Действие:* Выполнить перезапуск контейнера (Restart) в панели хостинга.
*   [ ] **Шаг 3. Проверить работоспособность `MAX_BOT_TOKEN`.**
    *   *Зачем:* Рассылка идет через API мессенджера. Если токен устарел или был отозван, отправка заблокируется.
    *   *Действие:* Отправить любое ручное текстовое сообщение от имени бота.

---

## ЧЕК-ЛИСТ 3: Бот вообще не отвечает на сообщения (Бот "умер")

Если бот не реагирует ни на текст, ни на голос:

*   [ ] **Шаг 1. Проверить статус сервера (Health Check).**
    *   *Действие:* Открыть в браузере адрес `https://твой-домен.com/api/health`. Если возвращается `{ "status": "ok" }`, значит веб-сервер жив. Если страница выдает ошибку 502/503 — сервер упал.
*   [ ] **Шаг 2. Проверить баланс и лимиты API ключей.**
    *   *Зачем:* При нулевом балансе или превышении лимитов (Rate Limit) на аккаунтах Google Gemini или Groq, LLM-движок будет возвращать ошибки 401/429, из-за чего бот не сможет сформулировать ответ.
    *   *Действие:* Проверить баланс в Google Cloud Console и Groq Console.
*   [ ] **Шаг 3. Проверить логи на наличие ошибок базы данных.**
    *   *Зачем:* База SQLite может заблокироваться (ошибка `SQLITE_BUSY: database is locked`), если транзакция зависла.
    *   *Действие:* Перезапустить сервер приложений для сброса всех активных подключений к базе.
*   [ ] **Шаг 4. Убедиться, что вебхуки от MAX доходят до сервера.**
    *   *Действие:* Открыть логи сервера и отправить боту сообщение. В логах должны появиться входящие запросы POST на адрес `/api/webhook` или `/webhook`.

## ЧЕК-ЛИСТ 4: Упал деплой (Ошибка при обновлении приложения)

Если при выкатке новой версии исходного кода сборка падает с ошибкой:

*   [ ] **Шаг 1. Запустить проверку компиляции.**
    *   *Действие:* Открыть терминал в папке проекта и выполнить команду: `npx tsc --noEmit`. Это покажет все ошибки в типах данных TypeScript. Исправить найденные ошибки.
*   [ ] **Шаг 2. Проверить файл `package.json`.**
    *   *Зачем:* Если в файле допущена синтаксическая ошибка (лишняя запятая, незакрытая скобка) или указана несуществующая версия библиотеки, сборщик пакетов npm упадет.
*   [ ] **Шаг 3. Убедиться, что в панели хостинга заданы переменные окружения.**
    *   *Зачем:* Для успешной сборки и запуска приложению критически необходима переменная `JWT_SECRET` (и остальные обязательные переменные из Чек-листа 1 в `docs/ENV.md`). Если на новом сервере их забыли прописать, деплой упадет при старте.
